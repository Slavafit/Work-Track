# Черновики предложений

С версии 2.16 приложение автоматически сохраняет состояние одного редактора предложения на устройстве: выбранный объект, идентификатор редактируемого предложения, услуги, материалы и введённые суммы. Незавершённые и некорректные значения сохраняются без преобразования, чтобы можно было продолжить ввод после повторного запуска.

Автосохранение не добавляет предложение в список сохранённых: для этого нужна кнопка сохранения. После успешного сохранения редактор запоминает идентификатор предложения, чтобы следующая запись обновляла его. Ошибка сохранения сохраняет введённые изменения.

Кнопка «Удалить черновик» запрашивает подтверждение и очищает редактор. Она не удаляет ранее сохранённое предложение. Переход к другому предложению и создание нового также требуют подтверждения, если текущий черновик изменён. При повторном запуске локальное состояние имеет приоритет над старым состоянием Activity, поэтому удалённый черновик не возвращается.

Хранение: отдельный SharedPreferences `proposal_draft`, JSON версии 1. Временные состояния загрузки, записи и ошибки не сохраняются. Android записывает изменения в фоне через `apply()`: внезапное завершение процесса до окончания записи или ошибка диска могут привести к потере последних изменений. Это не журнал с гарантией записи каждого нажатия при аварийном отключении. Удаление данных приложения удаляет и черновик.

Черновик исключён из системного переноса Android и ручного ZIP. Восстановление рабочей базы очищает редактор. При повреждении JSON приложение показывает сообщение; сохранённые предложения в базе не затрагиваются.

Локальные тесты проверяют запись на диск, создание нового редактора без SavedStateHandle, незаполненные строки, приоритет очистки над старым состоянием Activity, ошибку сохранения, сохранённый идентификатор, удаление предложения и повреждённую запись. Реальная принудительная остановка приложения на Android ещё требует проверки на устройстве.
